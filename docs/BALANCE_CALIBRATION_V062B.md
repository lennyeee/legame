# v0.62-B 首轮战斗校准记录

本轮是首次校准，不是“平衡完成”。真人 v0.62-C 试玩优先；未修改权威设计基线、AI实现、来财经济/概率、技能机制或地图。

## 复现方法

```text
npm run balance
npm run balance -- --scenario=mid
npm run balance -- --scenario=mid --reference-pressure
npm run balance -- --scenario=mid --json
```

脚本沿用项目测试的 Node TypeScript loader，需要支持 `registerHooks` / `stripTypeScriptTypes` 的当前开发环境 Node。没有新增依赖。

`src/balance/simulator.ts` 创建正式 `Match`、两份独立 `PlayerSide`，使用生产 `testMap`、真实 `CombatSimulation` 与正常 `1000/60ms` fixed step。只包装正式出怪/来财入口观察事件，不复制伤害、技能、EXP、升级或扣钱算法。结束后调用 Match.destroy。

`src/balance/scenarios.ts` 集中固定阵容及指标参数。双方使用同一分析阵容，但对象独立，避免空对手提前结束观测。分析 fixture 可打开阵容所需土地，并通过正式 drop 部署；这不是正式开局，也不向玩家/AI发单位。正式开局仍为 $20、空备战区、6块开放地。默认不持续升级、不来财、不携带道具、不调用AI；可用 `operate` 注入合法操作脚本并固定随机源。

JSON 包含阵容/坐标、loadout、压力/战斗/技能配置快照、逐波出生群统计、每5秒的积怪/现金/HP/来财机会采样、武将等级里程碑、最终构成。出怪群保留原始wave，避免重叠时把所有敌人误算为HUD当前wave。

## 指标定义

- 积怪：至少6只存活敌人，且至少一只到达30%路径，持续3秒；表格记录该段开始时间。
- 漏怪/失败：正式逃逸事件/Match结束；表格wave为当时HUD时间轴wave，不一定是漏怪敌人出生wave。
- 入口压制：一波所有计划敌人已生成且全部击杀，平均击杀存活时间≤1.5秒、最大路径进度≤15%；连续满足的出生群跨度为压制时长，包含波间间隔。
- 平均存活：已击杀敌人的平均存活时间，不混入漏怪。JSON另有最大路径进度及存活数量趋势。
- 理论来财机会：复制当前招募状态，在独立副本上调用正式 recruit，直到资金不足，得到当前预算能支付的连续来财次数；不窥探真实随机源，不给实际对局收益。实际成功次数/花费另行记录。
- 最长观测15分钟。到时未失败只能说明该窗口内守住，不能证明永远守住。

## 旧压力为何过软

原 v0.62-A 测量中，中期普通阵容15分钟内未漏怪，两个Lv5核心约第31波才漏怪，连续入口压制约378秒。采用当前受击规则、冻结旧pressure复测，中期阵容仍15分钟无漏怪，击杀621只、入口压制377.3秒。因此仅改善受击体验不足以消除压力落后。

`--reference-pressure` 只冻结旧压力：基础HP90、5波阶段、HP阶段+35%/阶段内+5%、数量阶段+2/每两步+1、5波脉冲+2、20秒波启动、2秒出怪逐阶段减少150ms最低500ms。它使用当前Combat/body/EXP，不等同于逐位复刻旧版本。

## 本轮参数

设波次w≥1，s=floor((w−1)/3)，r=(w−1)%3：

| 参数 | v0.62-B |
|---|---|
| 单敌HP | round(120 × (1 + 0.9s + 0.45s² + 0.4r)) |
| 单波数量 | min(32, 5 + floor(s/3) + floor(r/100) + 脉冲)；r<3故阶段内数量不增 |
| 脉冲 | 每6波多1只，HP/间隔不额外加成 |
| 波内出怪间隔 | max(800, 1800 − 35s) ms |
| 波启动时间 | 9500 + 12000 × (w−1) ms |
| 移速/击杀钱 | 55逻辑px/s；即时$1，未修改 |
| HP安全处理 | 封顶安全整数；波数仍无限，无清场门槛 |

HP负责韧性；数量缓慢增长控制收入和AOE价值；更短启动节奏负责连续压力。增长为阶段二次项，不是指数。Wave1～6 HP分别120/168/216/282/330/378，Wave10/17/24为930/2058/3618。

活怪可跨早期波启动时刻共存；本组参数早期不一定跨波同时继续生成旧波敌人。默认首次真正“新波开始后旧波仍有待生成事件”的测试样例为108→109波，基础设施仍支持任意交错；不得将活怪重叠与出怪事件重叠混称。原作wave3→4的精确密度关系尚未机械复刻，留待真人验证。

普通兵伤害成长1.55倍/级、间隔成长每级+0.08速度保持原样。武将普攻10/15/20/25/30、间隔/射程保持原样，不改技能配置和机制。

武将单敌参战EXP：10→5，升级需求仍30/50/70/90，总240。新压力下旧10EXP测得三名武将约65.5～66.3秒在第5波达到Lv5；改5后支援场景约120～123秒、第10波满级。仍是每个有效参战者获得完整奖励、不分摊、允许溢出、拆组丢未满EXP、Lv5封顶。

升级符CD20→50秒；其他道具CD、合法目标、+1级效果、pause及重开规则不改。

## 经济及局限

新mid平均击杀约22.7只/分钟，旧压力同阵容约41.4只/分钟。新mid结束$85，预算可连续来财5次；两个Lv5核心结束$67可4次；F2结束$182可9次。这是“不花钱”固定阵容的现金上限观察，不能解释成真人真的执行了这些来财或得到了对应升级。

合法脚本测试另外核对真实来财扣费/部署及花费记录。两把邻路Lv1刀在第一波能击杀至少2只且保持3HP，证明存在既定 $20→花10→击杀2只→可花12 的开局路径，不表示任意随机第一次来财都必然成功。

当前证据支持先纠正压力，不支持直接修改kill+$1或来财价格。数量增长已放缓；真人大量现金可能来自无需继续成长，也可能受实际操作/阵容影响，不能凭固定不花钱场景断言唯一原因。未来若真实主动消费轨迹仍证实收入过高，再单独提出方案。

固定阵容不模拟真人自然抽卡/成长，也不是正式AI性能评估；普通兵测试无道具，不代表50秒升级符的全部实战收益。双方使用同阵容，败局通常是同时HP0；不用于比较胜率。

## v0.62-C 必须人工验证

1. 初次随机来财的开局容错、第二次来财资金与9.5秒准备是否舒服。
2. 关键升级后是否能舒服1～2波，而不是永久挂机或升级也无收益。
3. 当前三波阶段、二次HP增长、12秒启动及波内密度是否过急；原作早期重叠关系是否需要进一步靠近。
4. 50秒升级符使用频率、5EXP下正常成将时间/成长是否合适。
5. 枪/骑隔一格的体感、刀90范围、42视觉直径/20受击半径是否清楚。
6. 实战主动消费后的现金积累、强阵持续成长后的局长、现有AI在新压力下的表现。

本轮不处理：AI强化、技能重做、招募/经济调整、正式资源、bundle优化、文案债务或其他架构改造。已知500kB构建提示可以保留。不存在模拟器自动搜索/优化参数。
