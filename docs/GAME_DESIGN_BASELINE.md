# legame Game Design Baseline

设计 Source of Truth。基线建立日期：2026-09-28；只读核对代码：v0.60，commit `bd2631f`。本文以用户本次提供的权威规格固化正式规则；代码、README 和测试只用于说明实现状态，不能覆盖设计。

## 阅读和维护

- ✅ 已确认规则：后续开发必须遵守，包括已确认但尚未实现的方向。✅ 不代表代码已经实现。
- 🟡 方向已确认，但具体数值、时序、概率或平衡仍需试玩；当前测试值只能作为当前值引用。
- ⬜ 尚未设计/尚未最终确认：列为待决定，不擅自填补。
- **过渡实现**：当前代码事实，单独列出，不能提升为正式设计。
- **Superseded / Deprecated Decisions**：已经明确废弃的方案，不因旧资料或旧测试而复活。

本正文完整保留权威规格的40个主题；AI详细规则见 [AI_DESIGN_BASELINE.md](AI_DESIGN_BASELINE.md)。同一主题有✅规则和🟡数字时，分别按正文说明判断。后续用户的新确认先更新此处，再实现代码；本次没有修改游戏实现。

## 一、设计资料优先级

> ✅ 已确认规则。

以后判断游戏规则时，证据优先级固定为：

1. 用户后来亲自确认的规则 / 明确纠正
2. 用户实际试玩、录像、截图确认的原作行为
3. 已经审核过的项目设计总结
4. 早期资料、旧方案
5. 猜测

后面的明确决定可以覆盖前面的旧设计。

绝对不能因为当前代码“现在就是这么写的”，就自动把它认定为正式游戏设计。

尤其注意：
v0.60 中存在大量过渡实现。

例如：
- 当前 v0.60-C 首怪约第 2 秒出现，是过渡测试时间，不是正式设计；
- 当前旧 20 波参数/HP/count 是过渡兼容数据；
- 正式比赛未来是无限固定时间轴；
- 旧 WaveProgress 不是正式未来架构。

文档必须明确区分：
✅ 已确认规则
🟡 方向已经确认，但具体数字/平衡仍待试玩调整
⬜ 尚未设计/尚未最终确认

另外建立：
Superseded / Deprecated Decisions
用于记录已经明确废弃、绝不能因为旧资料重新复活的方案。

## 二、项目核心定位

> ✅ 已确认规则。

这是一个私人双人 H5/Web 游戏，灵感来自抖音小游戏《赵云与阿斗》。

核心循环：

招募中国字单位
→ 在 5 格备战区处理单位
→ 部署/合成/升级
→ 用两个正确汉字横向组成武将
→ 布置防守
→ 自动塔防
→ 保护“乐”
→ 与另一名玩家/AI进行同场对战。

正式主模式叫“对战”。

早期由伪装成真人资料的 AI 作为对手；
后期 v0.95 接入真正 PVP。

不要在正式界面把对手标记为“AI”。

## 三、棋盘 / 双边规则

> ✅ 已确认规则。

棋盘逻辑尺寸：
8×5。

每个玩家：
- 自己永远显示在屏幕下方；
- 对手永远显示在屏幕上方。

双方使用同一个逻辑地图基础。

上方地图不是单独维护的第二张地图，
而是下方逻辑地图进行真正的 180° 显示变换：
上下翻转 + 左右翻转。

文字、等级、HP 等信息保持正常朝向，不跟随地图倒转。

当前基础地图：
28 个非路径土地：
- 初始开放 6 格
- 锁定 22 格

zero-based 初始开放坐标：
(1,0)
(2,0)
(3,0)
(5,0)
(4,1)
(4,2)

全部为普通土地。

未来地图计划：
- 厦门
- 本溪
- 济宁
- 福州
- 香港

使用同一逻辑体系，但道路/土地形状可以不同。

v0.60 双战场视觉已确认：
- 上下双方正常同等颜色/透明度；
- 上方不能做成 faded/disabled；
- 中央为 6px 深色中性灰绿色分界带；
- 上场整体上移 3px；
- 下场整体下移 3px；
- 不用红/绿阵营染色。

## 四、生命与胜负

> ✅ 已确认规则。

“乐”初始 3 HP。

敌人到达终点：
对应玩家自己的乐 -1 HP。

双方生命完全独立。

任意一方首先到 0：
另一方胜利。

如果在同一个 logical step 中双方同时变成 0：
平局。

必须避免 update 顺序造成胜负偏差。

Match 结束后：
双方全部逻辑冻结。

包括：
- 刷怪
- 敌人移动
- 普通攻击
- 弹道
- 武将技能/充能
- Farmer
- 铁饭碗
- 主动道具 CD
- 玩家/AI操作

## 五、招募与 5 格压力

> ✅ 已确认规则。

备战区固定 5 格。

正式开局：
备战区为空。

来财会一次性刷新/替换全部 5 格。

无论里面有没有东西：
仍留在备战区里的东西都会消失。

不存在：
- 确认弹窗
- 锁定格
- 自动保护
- 隐藏仓库
- AI 专属仓库

棋盘本身允许作为临时仓库。
玩家可以把暂时不想被刷掉的单位/武将字放到棋盘。

这是核心策略压力之一，不得轻易弱化。

## 六、正式经济

> ✅ 已确认规则。

每局开始：
$20。

第一次成功来财：
$10。

以后每次成功来财价格 +$2：

10 → 12 → 14 → 16 → ...

只有“成功招募”才：
- 扣钱
- 刷新
- 增加招募次数
- 推进下次价格

钱不足：
什么都不发生。

没有无条件的每秒收入。

基础敌人死亡：
立即 +$1。

双方经济独立。

更快杀怪的一方可以更早拿到钱，这是正常差异。

当前没有：
- 每波固定奖励
- 时间奖励
- 掉血补偿
- comeback compensation

开局关系必须保留：

$20
→ 第一次来财 $10
→ 剩 $10
→ 至少击杀 2 个基础敌人
→ 才够第二次 $12。

## 十一、武将组成

> ✅ 已确认规则。

当前武将：

小|美 → xiaomei
阿|饼 → abing
小|六 → xiaoliu

可招募字：
小、美、阿、饼、六。

“小”是共享字。

未来计划约 12 个武将，
共享字网络是刻意设计，不是 bug。

武将只能通过：

两个正确名字字
横向相邻
正确左→右顺序

激活。

以下都不能激活：
- 纵向
- 对角
- 不相邻
- 反向

未激活/孤立的棋盘武将字：
睡眠状态，
不攻击，
显示 Zz。

备战区的字不显示睡眠。

武将激活后：
仍然占两个独立格子。
两个字仍是两个独立 occupant。

视觉上弱化/消失中间分隔，
形成 2×1 外框，
但不能把名字变成一个居中的单独对象。

动态激活/失活。

原 active hero 被拆掉后：
候选组合可以重新激活。

## 十三、武将等级

> ✅ 已确认规则。

武将等级永久存储在 HeroLetter 上，
不是 HeroLink。

新字 Lv1。

移动保持等级。

两个字形成 active hero 时：
两边同步到较高等级，
只向上同步，
绝不降级。

最高 Lv5。

共享字的等级会自然传播到它参与的新武将。

同字叠加升级：

同一个字拖到同一个字：
消耗 material，
target +1 Lv。

material 自己等级无关。

最高 Lv5。

Lv5 再叠加：
失败，
不消耗。

## 十四、武将 EXP

> ✅ 规则或方向已确认；🟡 试验数值、时间及平衡目标按本节说明维护；⬜ 未定细节不得自行补全。

EXP 属于当前 active HeroLink，
不是永久属于字。

新 HeroLink 激活：
EXP = 0。

拆开：
未填满 EXP 丢失。

重新组成：
重新从 0 开始。

可以 overflow / 一次多级升级，
最高 Lv5。

参与判定：

active hero 对某敌人造成 >0 damage
→ 记录 participation。

敌人死亡时：
每个仍然有效的 participating active hero
获得完整 EXP。

不分摊。

同一个 hero 对同一个敌人只记一次参与。

敌人死前 hero 被拆：
失去有效 participation。

重新激活后：
必须重新对敌人造成伤害才重新参与。

当前 EXP 阈值/敌人 EXP 数值属于暂定平衡。

## 二十一、正式 Match 时间轴

正式比赛不是：
“清完这一波才开始下一波”。

正式规则：

双方共享一个固定 global spawn timeline。

同一个 spawn event：
在双方各自战场生成独立 enemy entity。

双方：
- schedule 相同
- enemy type/count/base HP 相同
- 实体独立
- combat 独立
- HP 独立
- kill/economy 独立

时间轴永远不等待玩家清怪。

积怪不会阻止下一批生成。

允许 wave overlap。

正式模式无限推进，
没有最终 wave。

没有“撑到第20波就赢”。

胜负只来自：
某方乐先归 0，
或者同 logical step 双方同时归 0 = draw。

敌人移动速度计划保持固定。

压力主要通过：
- HP
- 数量
- spawn density

增长。

增长不是完全均匀线性，
允许不同阶段权重变化和偶发相同压力 pulse。

目标体验：

吃力
→ 升级/调整
→ 舒服 1–2 个阶段
→ 压力追上
→ 再升级。

目标局长：

普通局：
约 5–8 分钟。

早期失误：
可能 1–3 分钟结束。

强阵容：
10+ 分钟。

理论上可以无限，

最终应该被无限增长压力追上。

## 二十四、正式完整比赛流程

> ✅ v0.63 已确认流程规则；🟡 当前低保真表现时间可在后续动画阶段调整，不代表永久美术规格。

正式流程：

HOME → HOME内MATCHING → VS → INTRO → RUNNING → RESULT。

- HOME点击开始对战后原主页保持可见并锁定操作，在原主页内展示匹配反馈。
- 每次匹配生成新的OpponentProfile和不可变BattleSetup；双方loadout快照用于新Match。
- VS双方资料从上下滑入、停留，再向上下散开露出战场。Match从VS散开开始计时（Match time 0），不是从网页加载或匹配开始计时。
- INTRO期间乐沿本方路径入场，双方表现独立且文字正向。玩家已经可以来财、拖放、合并、铲地。不增加3、2、1倒计时。
- 当前首怪为Match time 9500ms，仍使用正式无限压力时间轴；不得恢复旧清场推进或20波结束规则。
- 任一方HP归零，在双方完成同一个fixed logic step后判定结果；同一步双方归零为draw。RESULT立即冻结双方Timeline、Combat、AI、Farmer、道具CD、经济和乐表现，同时立即禁止全部战场操作。
- 最终战场画面保留约400ms，由仍活动的结果overlay Scene Clock负责延迟；不是继续运行Match或等待已暂停GameScene的时钟。
- v0.65将旧居中结果弹窗替换为独立全屏ResultScene，使用米白底色，显示胜利/失败/平局、第X波、击杀数、成功来财次数、剩余美金和本局金币奖励。只在胜利时显示玩家自己的剩余乐HP；失败/平局不显示HP或对手统计。保留最终战场400ms后停止旧GameScene并销毁Match，结果页只消费不可变ResultSnapshot与只读奖励数据，不依赖旧Match。
- Match-local不可变ResultSnapshot包含result（win/lose/draw）、waveReached、playerKills、playerSuccessfulRecruits、playerRemainingMoney、playerRemainingHp、opponentRemainingHp。统计包含最后一个逻辑步的kill/leak及即时奖励；波次为timeline.wave（实际已开始的最高波次，从1开始）。击杀直接累计本方正式kill事件，不从收入/EXP反推；来财次数和余额使用现有RecruitmentState。
- 再来一局：结束overlay与旧GameScene、销毁旧Match，进入同一HOME式匹配/VS/INTRO流程，生成新对手、Side、AI和Timeline。只保留玩家loadout，所有本局统计和运行状态归零。
- 返回主页：结束overlay与旧GameScene、销毁旧Match，恢复正常HOME的开始对战/道具按钮，不自动匹配；保留玩家装备配置。
- 退出必须清理旧timer/tween、update/input监听、LeIntroView、结果UI绑定和运行状态，旧回调不能污染新局。战斗暂停菜单只保留继续游戏/返回主页，不与RESULT同时存在。
- v0.64新增本节二十八定义的本地永久战绩与小数值金币；v0.66新增本节三十定义的永久段位与结果反馈。仍不显示MVP、伤害榜或对手统计。

当前可调整的低保真presentation参数：匹配2–3秒、VS滑入400ms、停留1400ms、散开500ms、乐入场7000ms、结果面板延迟400ms。它们用于当前已验收体验，未来视觉迭代可单独调整；流程时钟归属与清理规则仍需保持。首怪9500ms属于当前战斗节奏，本阶段没有重新调整。

### 状态与伤害来源

- 每个CombatSimulation独立持有StatusEffects，使用固定逻辑步处理，不依赖Phaser动画/Timer回调，不修改基础属性。

- slow以各有效因子相乘，最终至少基础速度25%。stun优先使移动为0，但DOT与slow及其他持续时间继续递减。结束后自动回到当时剩余状态对应速度。
